## 0. Rules for AI assistants (read first)

1. Find out which dev you are helping (A or B). Edit **only files that dev owns** (section 2). If you need a change in the other dev's files, tell the human to message them.
2. **No hardcoded AI output.** Scores, extracted skills, summaries, questions and search results must come from real Gemini calls or real embedding/vector math. Hardcoded AI responses do not count in grading.
3. Fixed stack: Next.js (App Router, TypeScript, Tailwind, no `src/`), Supabase (Postgres, Auth, Storage, pgvector), Gemini API, Vercel.
4. Do NOT create `middleware.ts` (this Next.js version uses `proxy.ts`). Protect pages with `requireRole()` inside layouts and actions.
5. `cookies()`, `params`, `searchParams` are async (Promises). Always `await` them.
6. Server Components by default. Use `'use client'` only for interactivity (state, effects, charts, dialogs).
7. Styling: Tailwind + shadcn/ui only. No new CSS files.
8. Every server action returns `ActionResult<T>` and validates input with `zod`.
9. Secrets never go in client code or git. `SUPABASE_SERVICE_ROLE_KEY` is server-only (no `NEXT_PUBLIC_` prefix).
10. Small commits, `git pull` often, never force push.

## 1. Project snapshot

**Goal:** AI-powered recruitment platform. Recruiters publish jobs, review ranked and explained candidates, shortlist, generate interview questions, schedule interviews, view analytics. Candidates keep a profile, upload a PDF resume, apply, track status. **Humans make all hiring decisions; AI only recommends and explains.**

**Rubric (100):** Architecture & completeness 30 | AI & matching quality 25 | Resume parsing 15 | UI/UX 15 | Innovation, testing, security, deployment 15.
**Success = reliable end-to-end workflow with evidence-based explanations, not the most features.**

**Demo scenario:** Recruiter posts a Backend Developer job (Python, Django, PostgreSQL, Docker) -> 3 candidates upload resumes and apply -> system extracts evidence, scores with explanations, shows missing evidence -> recruiter reviews, shortlists one -> generates interview questions -> schedules interview -> dashboard updates.

**Scoring weights:** skills 50%, experience 25%, project relevance 15%, qualifications 10%.

## 7. Database schema (`supabase/schema.sql`, run once)

```sql
create extension if not exists vector;

create table profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  role text not null check (role in ('recruiter','candidate')),
  full_name text, email text, created_at timestamptz default now()
);
create or replace function handle_new_user() returns trigger
language plpgsql security definer set search_path = public as $$
begin
  insert into profiles (id, role, full_name, email)
  values (new.id, coalesce(new.raw_user_meta_data->>'role','candidate'),
          new.raw_user_meta_data->>'full_name', new.email);
  return new;
end $$;
create trigger on_auth_user_created after insert on auth.users
  for each row execute function handle_new_user();

create or replace function is_recruiter() returns boolean
language sql security definer stable set search_path = public as $$
  select exists (select 1 from profiles where id = auth.uid() and role = 'recruiter')
$$;

create table jobs (
  id uuid primary key default gen_random_uuid(),
  recruiter_id uuid not null references profiles(id),
  title text not null, department text, location text,
  type text default 'full-time', salary text, description text not null,
  skills jsonb not null default '[]',
  min_experience_years numeric default 0, qualifications text,
  status text not null default 'open' check (status in ('open','closed')),
  created_at timestamptz default now()
);

create table resumes (
  id uuid primary key default gen_random_uuid(),
  candidate_id uuid not null references profiles(id),
  file_name text, file_path text, raw_text text, parsed jsonb,
  status text not null default 'parsed' check (status in ('parsed','failed','empty')),
  error text, created_at timestamptz default now()
);

create table resume_chunks (
  id uuid primary key default gen_random_uuid(),
  resume_id uuid not null references resumes(id) on delete cascade,
  kind text not null check (kind in ('skill','experience','project','education','summary')),
  content text not null, embedding vector(768)
);

create table applications (
  id uuid primary key default gen_random_uuid(),
  job_id uuid not null references jobs(id) on delete cascade,
  candidate_id uuid not null references profiles(id),
  resume_id uuid not null references resumes(id),
  status text not null default 'submitted' check (status in
    ('submitted','parsed','assessed','review','shortlisted','rejected','interview','selected')),
  created_at timestamptz default now(), updated_at timestamptz default now(),
  unique (job_id, candidate_id)
);

create table assessments (   -- recruiter-only
  application_id uuid primary key references applications(id) on delete cascade,
  total_score numeric not null, breakdown jsonb not null, details jsonb not null,
  created_at timestamptz default now()
);

create table application_events (   -- audit trail
  id uuid primary key default gen_random_uuid(),
  application_id uuid not null references applications(id) on delete cascade,
  from_status text, to_status text not null,
  changed_by uuid references profiles(id), note text,
  created_at timestamptz default now()
);

create table recruiter_notes (
  id uuid primary key default gen_random_uuid(),
  application_id uuid not null references applications(id) on delete cascade,
  recruiter_id uuid not null references profiles(id),
  note text not null, created_at timestamptz default now()
);

create table interview_questions (
  id uuid primary key default gen_random_uuid(),
  application_id uuid not null references applications(id) on delete cascade,
  difficulty text not null check (difficulty in ('beginner','intermediate','advanced')),
  category text not null check (category in ('role','project')),
  question text not null, answer_guide text, created_at timestamptz default now()
);

create table interviews (
  id uuid primary key default gen_random_uuid(),
  application_id uuid not null references applications(id) on delete cascade,
  interviewer_name text not null, scheduled_at timestamptz not null,
  duration_min int default 45, type text default 'technical',
  feedback jsonb, decision text check (decision in ('selected','rejected')),
  created_at timestamptz default now()
);

create or replace function match_chunks(query_embedding vector(768), match_count int default 20)
returns table (resume_id uuid, chunk_id uuid, kind text, content text, similarity float)
language sql stable as $$
  select resume_id, id, kind, content, 1 - (embedding <=> query_embedding)
  from resume_chunks where embedding is not null
  order by embedding <=> query_embedding limit match_count;
$$;

insert into storage.buckets (id, name, public) values ('resumes','resumes', false)
on conflict do nothing;

do $$ declare t text; begin
  for t in select unnest(array['profiles','jobs','resumes','resume_chunks','applications',
    'assessments','application_events','recruiter_notes','interview_questions','interviews']) loop
    execute format('alter table %I enable row level security', t);
  end loop; end $$;

create policy profiles_read on profiles for select to authenticated using (id = auth.uid() or is_recruiter());
create policy jobs_read on jobs for select to authenticated using (true);
create policy jobs_write on jobs for all to authenticated
  using (is_recruiter() and recruiter_id = auth.uid()) with check (is_recruiter() and recruiter_id = auth.uid());
create policy resumes_read on resumes for select to authenticated using (candidate_id = auth.uid() or is_recruiter());
create policy resumes_own_write on resumes for all to authenticated
  using (candidate_id = auth.uid()) with check (candidate_id = auth.uid());
create policy chunks_read on resume_chunks for select to authenticated
  using (is_recruiter() or exists (select 1 from resumes r where r.id = resume_id and r.candidate_id = auth.uid()));
create policy apps_read on applications for select to authenticated using (candidate_id = auth.uid() or is_recruiter());
create policy apps_insert on applications for insert to authenticated
  with check (candidate_id = auth.uid() and status = 'submitted');
create policy apps_recruiter_update on applications for update to authenticated
  using (is_recruiter()) with check (is_recruiter());
create policy assess_read on assessments for select to authenticated using (is_recruiter());
create policy events_read on application_events for select to authenticated using (is_recruiter());
create policy events_insert on application_events for insert to authenticated with check (is_recruiter());
create policy notes_all on recruiter_notes for all to authenticated using (is_recruiter()) with check (is_recruiter());
create policy questions_all on interview_questions for all to authenticated using (is_recruiter()) with check (is_recruiter());
create policy interviews_all on interviews for all to authenticated using (is_recruiter()) with check (is_recruiter());
```

## 8. AI specs

### Dev A: resume parsing (`uploadResume`)
1. Validate: PDF mime type and magic bytes, size <= 4 MB. Reject anything else with a friendly message.
2. Extract text with `unpdf` (`getDocumentProxy` + `extractText`). Under ~50 characters -> save `status = 'empty'` (probably scanned) and tell the user to enter details manually. Wrap in try/catch -> `status = 'failed'` with a readable error. Never crash.
3. Gemini JSON mode with a schema -> `ParsedResume`, validated with zod. Retry once on 429.
4. **Normalize** skills via an alias map in `lib/ai/normalize.ts` (js/javascript -> JavaScript, postgres/postgresql -> PostgreSQL, py -> Python, node/nodejs -> Node.js, k8s -> Kubernetes...). Dedupe.
5. **Hallucination check** (`lib/ai/verify.ts`): each skill/project/experience `excerpt` must occur in the raw text (case/whitespace-insensitive). Else `verified = false`; unverified items never count toward the score and go into `unsupported_claims`.
6. Chunk (skills, each experience, each project, each education item, summary), embed in ONE batched call (768 dims), insert into `resume_chunks`. Upload the PDF to the private `resumes` bucket under `<candidate_id>/<file>`.

### Dev A: assessment (`applyToJob` -> `runAssessment`)
- **Fairness/privacy:** the scoring code receives only skills, years, projects, education degrees. Never name, email, phone, gender, age, photo, address, nationality.
- `skills` (50%): per job skill, `match = 1` on alias-normalized exact match; otherwise map the best cosine similarity between the skill embedding and the candidate's skill/project chunks linearly (`<= LOW -> 0`, `>= HIGH -> 1`, constants in `lib/ai/config.ts`, calibrate on the 3 demo resumes). Score = `sum(importance * match) / sum(importance) * 100`.
- `experience` (25%): `min(candidate_years / min_years, 1) * 100` (100 if no minimum).
- `projects` (15%): average of the top 2 similarities between the job description embedding and project/experience chunks, same mapping.
- `qualifications` (10%): from the explanation call below.
- `total = 0.5*skills + 0.25*experience + 0.15*projects + 0.10*qualifications`.
- One Gemini call (JSON mode) gets job requirements + verified evidence and returns `summary`, `learning_suggestions`, a qualification score + reason, and optional `explicit_absence_quote` per gap.
- **Gaps:** required skill with `match < 0.5`. Default `missing_evidence`. It becomes `confirmed_absent` only if the resume explicitly states the absence (quote verified in raw text) or a recruiter confirms via `correctSkills`.
- Save to `assessments`, status -> `assessed`, write audit events (submitted, parsed, assessed).

### Dev A stretch
- **Talent search:** embed the query, call `match_chunks`, group by resume, return similarity + matching chunks as evidence.
- **Job recommendations:** embed the candidate's verified skills/projects, compare with open jobs.
- **Fairness check:** re-run scoring on the same resume with a different name/gender-related terms; report whether the score changed.

### Dev B: AI features
- `extractRequirements(description)`: `generateJSON` -> `{skills: SkillRequirement[], min_experience_years, qualifications}`; fills the job form.
- `generateQuestions(applicationId)`: `generateJSON` with job, matched skills, gaps and candidate projects -> about 9 questions (3 per difficulty), at least 3 about the candidate's own projects, each with `answer_guide`. `regenerateQuestion` passes existing questions so it does not repeat them.
- **Scheduling conflicts:** same interviewer name or same candidate with an overlapping `[start, start + duration)` window -> return a readable conflict message; save only if `force` is true.
- **Analytics:** counts from `applications`; `avg_processing_hours` = average of (first recruiter decision event - application created); `common_gaps` aggregated from `assessments.details.gaps`.

## 10. Demo script and definition of done

1. Recruiter signs in, creates the **Backend Developer** job (paste description, click *Extract with AI*, adjust Python / Django / PostgreSQL / Docker).
2. Three candidates (strong / medium / weak) upload a PDF and apply.
3. Recruiter opens the ranked list, then the top candidate: score breakdown, matched skills with excerpts, gaps, unsupported-claim flags.
4. Add a private note, mark *Review*, **shortlist** one (audit trail updates).
5. Generate interview questions, edit one, regenerate one.
6. Schedule an interview, then try a conflicting slot to show the warning.
7. Dashboard counts and charts have changed. Show talent search if finished.

**Done =** this flow works on the **deployed Vercel URL** with no console errors, a candidate cannot open `/recruiter/*`, and the three demo resumes produce clearly different, explainable scores.
